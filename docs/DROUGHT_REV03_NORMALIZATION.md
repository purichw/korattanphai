# ข้อมูลพยากรณ์ภัยแล้ง rev03

## แหล่งข้อมูลและความหมาย

แหล่งข้อมูลเดียวคือ `Drought_T1-6_rev03.xlsx` ใน sheet
`Master_Data_Drought_Final` โดยใช้คำนิยามที่ผู้ใช้ยืนยันในวันที่ 6 กันยายน 2569
ไม่ได้ผสมค่าพยากรณ์ สถานะชลประทาน หรือข้อมูลพื้นที่จากชุดข้อมูลอื่น

- `Year` และ `Month` เป็นเดือนตั้งต้น T ของแถวนั้น ไม่ใช่เดือนปลายทาง
- `Pred_Risk_T+1` ถึง `Pred_Risk_T+6` คือค่าพยากรณ์ของหกเดือนถัดไป
- `target_month = source_month + horizon_months` โดยบวกเดือนปฏิทิน
- ไม่มีข้อมูลวันหรือเวลาออกพยากรณ์ จึงเก็บวันที่ระดับเดือน `YYYY-MM`
  และไม่สมมติวันออกพยากรณ์ให้เป็นวันที่ 1
- ทุกค่าเป็นการพยากรณ์ ไม่ใช่ผลสังเกตภัยแล้งจริงหรือความเสียหายที่ยืนยันแล้ว

| ค่าความเสี่ยง | ความหมาย | scope_status |
|---|---|---|
| 0 | ไม่พบสัญญาณเสี่ยง | in_scope |
| 1 | เสี่ยงปานกลาง | in_scope |
| 2 | เสี่ยงสูง | in_scope |
| ว่าง | อยู่นอกขอบเขตการศึกษา (การพยากรณ์) | out_of_scope |

ค่าว่างเป็น `null` ใน JSON และช่องว่างใน CSV โดยมี `scope_status` กำกับเสมอ
ไม่ใช้ 0 แทนค่าว่าง และไม่สร้างแถวค่าว่างเพื่อชดเชยแถวที่หายไป

| สถานะชลประทาน | ความหมาย |
|---|---|
| Collecting | ยังไม่มีข้อมูล |
| RainFed | พึ่งน้ำฝน (ไม่มีชลประทาน) |
| Irrigation | เข้าถึงชลประทาน |

ตัวอ่านรองรับการสะกด `Irragation` เป็น `Irrigation` และเก็บคำเดิมใน
`irrigation_status_raw` เสมอ ไฟล์ที่ตรวจครั้งนี้ใช้ `Irrigation` อยู่แล้ว
สถานะชลประทานเป็นคนละมิติกับความเสี่ยง ห้ามใช้แทนกันหรืออนุมานข้ามกัน
ในไฟล์นี้สถานะคงที่ต่อ ID แต่ไม่มีวันที่สำรวจสถานะชลประทานแยกต่างหาก

### forecast_values.csv

| คอลัมน์ | ชนิดและความหมาย |
|---|---|
| source_id | ข้อความรหัส ID ตาม workbook รวม ID 0 ไม่ใช่รหัสเขตการปกครอง |
| source_month | เดือนตั้งต้น T รูปแบบ YYYY-MM ค.ศ. |
| horizon_months | จำนวนเต็ม 1 ถึง 6 |
| target_month | เดือนตั้งต้นบวก horizon_months รูปแบบ YYYY-MM ค.ศ. |
| risk_value | จำนวนเต็ม 0/1/2 หรือ null |
| scope_status | in_scope หรือ out_of_scope |
| source_first_row | เลขแถว Excel แรกของรายการก่อนแตกเป็น T+1 ถึง T+6 |
| source_row_count | จำนวนครั้งที่แถวต้นฉบับที่เหมือนกันปรากฏ |

Primary key ภายในชุดข้อมูลคือ `source_id + source_month + horizon_months`
หากจัดเก็บหลายชุดข้อมูลต้องเพิ่ม `dataset_id` ด้วย เดือนปลายทางเพียงอย่างเดียว
ไม่ใช่คีย์ เพราะคนละเดือนตั้งต้นและคนละ T+ อาจพยากรณ์เดือนปลายทางเดียวกันได้

เชื่อม `forecast_values.source_id` กับ `locations.source_id` เพื่ออ่านชื่อและ
สถานะชลประทาน ส่วน `source_row_lineage.retained_source_row` เชื่อมกับ
`forecast_values.source_first_row` เพื่อย้อนกลับถึงแถวต้นทางทั้งหมด
ชื่อ sheet และ hash ของ workbook อยู่ใน manifest ไม่ต้องทำซ้ำทุกแถว

JSON ใช้ `packedRiskBySourceMonth[source_month][source_id]` เป็น array
หกค่าเรียง T+1 ถึง T+6 ค่าที่เท่ากันยังคงเป็นคนละรายการพยากรณ์
CSV ใช้ UTF-8 พร้อม BOM และหัวคอลัมน์คงที่

## ข้อควรระวัง

1. ไฟล์สิ้นสุดที่เดือนตั้งต้น ธ.ค. 2568 ไม่ใช่เดือนปัจจุบันของระบบ
   ไม่มีเดือนตั้งต้นในปี 2569 และไม่เติมข้อมูลให้ยาวถึงปัจจุบันเอง
2. ID `5` และ `222` มีชื่อ `Nong Rawiang / Mueang Nakhon Ratchasima`
   เหมือนกันในต้นฉบับ แต่เป็นคนละ ID จึงเก็บแยกโดยไม่แก้ชื่อหรือรวมข้อมูล
   ผู้ใช้ยืนยันภายหลังว่า ID `222` อยู่ อ.พิมาย ส่วน ID `5` อยู่ อ.เมืองนครราชสีมา
   การแก้ mapping เก็บแยกจากชื่อดิบใน normalized โดยไม่แก้ต้นฉบับหรือรวม ID
   ดูรายละเอียดและผลตรวจใน `DROUGHT_REV03_CUTOVER.md`
3. ชุดนี้ไม่มีรหัสเขตการปกครองที่อนุมานจากแหล่งอื่น ไม่มีขอบเขตแผนที่
   ไม่มีข้อมูลพืช พื้นที่เพาะปลูก ความเสียหายจริง หรือค่าความแม่นยำของแบบจำลอง
4. ความครบถ้วนของการนำเข้าไม่ใช่ความครอบคลุมการพยากรณ์ ทุก ID/เดือน/T+
   มีรายการครบ แต่รายการที่เป็น null ยังอยู่นอกขอบเขตการพยากรณ์
